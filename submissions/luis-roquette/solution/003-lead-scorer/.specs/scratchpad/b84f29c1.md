### Entry 1: temporal prediction and calibration

Objective: establish leakage-safe probability contracts. Action: read R01–R07 and source R21. Observation (high confidence): freeze an already-trained pipeline, calibrate on a later disjoint interval, evaluate on an untouched final interval; default stratified CV is not a chronological split. Both losses and reliability bands are needed. Sigmoid's affine mapping in log-odds allows exact directional explanations. New question resolved by policy recommendation: selecting repeatedly against a final test makes it development data. Freeze hyperparameters, band boundaries, eligibility and candidate-choice rules before evaluating test once. If ranking comparisons choose the winner on that final set, disclose post-selection optimism and require new future validation rather than calling the winner's estimate unbiased.

### Entry 2: data validation and unavailable account attributes

Objective: preserve invalid rows while making usable history safe. Action: read R10/R24 and task contract. Observation (high confidence): validate dimension-key uniqueness/nulls before left merges; audit join indicators and row counts. Normalize the one known product alias explicitly; no fuzzy matching. Missing accounts route to an intentionally account-free pipeline; do not replace them with an average account. Full and fallback routes require independent diagnostics; train fallback on projected historical rows, and also report natural missing-account subgroups where counts permit. Empty, one-class, missing-key or too-small time periods block probability publication. Dataset counts and actual field validity remain unmeasured at research phase.

### Entry 3: explanations and alternatives

Objective: explain the actual decision score without a fragile dependency chain. Action: examine R04/R05/R17–R21 and R32/R33. Observation (high confidence for APIs; medium for unimplemented integration): logistic transformed feature contributions sum to the margin. A tree path can telescope child-minus-parent node values into the leaf prediction, weighted by boosting learning rate and including its initial margin. This is a faithful path decomposition, not SHAP and not causal attribution; attribution can depend on split order. A final sigmoid calibration adds an affine transform in log-odds, which scales contributions and can reverse signs if its slope reverses. Test reconstruction of both raw margin and calibrated probability. TreeSHAP is a viable optional alternative but latest release conflicts with Python 3.11; older-compatible SHAP needs an actual compatibility smoke test with chosen sklearn before being recommended for installation. Do not use global feature_importances_ as local explanations.

### Entry 4: sparse relative evidence

Objective: avoid unsupported Prospecting probabilities. Action: examine R08/R09 and task's labeling limitation. Observation (high confidence for smoothing; application hierarchy is a recommendation): category smoothing shrinks small samples. Generic formula `(wins + alpha * parent_rate) / (n + alpha)` gives an auditable relative index; closed-history base rate is not a probability for the unsampled Prospecting population. Predeclare a nested backoff chain, e.g. product+seller+account → product+seller → product → global. Display observed n, prior strength alpha, chosen level and effective support; do not label n+alpha as independent observed deals or add overlapping groups' n. All-history retrospective group encoding would leak during evaluation; use training history only or chronological cross-fitting. No historical Prospecting outcomes exist to validate a prospect-to-close probability.

### Entry 5: UI lifecycle and local reproducibility

Objective: avoid retraining and pin leakage across users. Action: read R11–R16/R22. Observation (high confidence): pass data-byte and canonical scoring-config hashes to the training cache. Keep cached model bundle immutable; pins live only in session state, with manager/timestamp and a calculation generation; clear on explicit recalculation even when bytes/config remain identical. Native dataframe selection plus columns suffices for a side details panel. Reset stale selection when filter/stage/portfolio changes, map positions back to opportunity IDs. A demo role selector is not authentication. AppTest is complementary to a real rendered browser walkthrough. Do not put pins into shared cached data or confuse Cloud build/startup with validated live UX.

### Option comparison

|---|---|---|---|---|
| Regularized logistic + sigmoid calibration | Minimal, coefficient explanation, fast expected at this scale | Misses nonlinear interactions; calibration can still fail | sklearn 1.9.1 supports Python 3.11; active; no extra serialization | Preferred unless validated boosting wins consistently |
| GradientBoostingClassifier + sigmoid + exact path decomposition | Nonlinear candidate; no extra package; additive local raw-score reconstruction | More fitting and explanation checks; path attribution is order-dependent | Same sklearn; uses public tree attributes; must fix default constant init and binary loss contract | Required comparison candidate |
| GradientBoostingClassifier + TreeSHAP | Established local attribution with explicit output-space contract | More dependencies; Python 3.11 requires older SHAP; calibration wrapper still separate | SHAP 0.49.1 metadata-compatible with Python; sklearn 1.9.1 runtime unverified | Viable if path attribution is inadequate and compatibility proved |
| Smoothed group evidence / relative-only bands | Transparent, robust backoff, small implementation | Not calibrated prospect-to-close probability; seller selection bias | pandas/stdlib only; test arithmetic and historical boundaries | Required Prospecting route and clearly labeled nonprobability fallback |

### Risks and mitigations

| Risk | Impact / likelihood | Mitigation |
|---|---|---|

| Static account snapshot treated as historical point-in-time truth | High / medium | Document provenance and uncertainty; exclude mutable features without decision-time justification; do not claim full historical reconstruction |
| Wrong eligibility coverage | High / medium | Gate each route separately, report account availability, product support and subgroup sample counts; never borrow a passed route's validation |
| Score contributions confused with probability percentage points | High / high | State units; test additive margin and final sigmoid reconstruction; handle sign reversal |
