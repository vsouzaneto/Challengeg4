## Stage 3: Sequential Solving

No existing executable code is present. Reuse stdlib recovery/hash/JSON, pandas validated joins, sklearn pipelines/frozen sigmoid, native Streamlit and unittest. Source/contracts already settle all algorithm choices; do not reopen them through trial on the final test. 01 supplies parsed records and fixture helpers to 02a/02b. 02b supplies stable C3 records/fixture builders to 03a/03b. 04 consumes both implementations and owns final integration/runtime verification. 05 consumes frozen proof; 06 consumes actual deployment evidence.

## Stage 4: Implementation Strategy Selection

Shape: risk-first evidence pipeline with contract-based UI overlap. The early independently runnable solution is a validated data/recovery tool plus callable four-route evaluation and passing tests; the next is the complete interactive application. This permits width two without concurrent edits to scoring.py or app tests. Three modules are mandated; introducing a fourth to widen work would increase scope.

## Stage 5: Task Breakdown Strategy

12 draft work units consolidated into 8 steps: environment/test setup + ingestion -> 01; calibration + candidate evaluation -> 02b; explanations/actions + state prioritization -> 03a; browser capture + Cloud proof -> 05. Four standalone runs removed. Recovery remains separate because transaction failure handling is independently testable and otherwise overloads ingestion. Statistical evaluation and active-score attribution remain distinct large steps (each <=2 days) because of materially different risk and a stable intermediate contract. No separate testing-only phase; tests belong to each producing step.
